# 固定地图 Web Radar：设计与实施方案

## 目标与边界

Web Radar 是现有 SDL2/ImGui 覆盖层之外的独立功能。它使用浏览器显示固定北向的完整地图，服务端内嵌在主程序中，不启动 Node.js 或额外的 Web 服务进程。

本实现以 `cs2_webradar` 的用户能力作为需求参考，但协议、C++ 服务端和 React 前端均重新设计和实现，不复制其源代码。原项目的 GPL-3.0 代码不会进入本仓库；CivetWeb 使用 MIT 许可的 v1.16 固定版本。

项目仍然只允许在以 `-insecure` 启动的离线环境中学习和测试。Web Radar 不改变这一使用边界，也不应暴露到互联网。

## 最终方案

```text
CS2 只读采样
    │
    ▼
GameSnapshot（完整、绝对状态）
    ├── 现有 ESP/本地功能读取
    └── JSON v1 序列化（有界、无地址字段）
             │
             ▼
      CivetWeb 内嵌服务
      ├── 静态文件：web-radar/dist
      ├── 状态接口：/api/v1/status
      └── WebSocket：/api/v1/stream?token=...
             │
             ▼
      React 固定北向地图 UI
      ├── 玩家位置、朝向、存活状态与装备
      ├── C4 携带/掉落/安放与倒计时
      ├── CT/T 队伍面板
      └── 断线重连、过期状态与本地显示设置
```

选择该方案的原因：

- 固定北向全地图与玩家视角解耦，符合共享战术面板的阅读方式，不保留圆形、旋转或距离裁剪雷达。
- `GameSnapshot` 是采样器与网络层之间唯一的数据契约。网络线程不直接读游戏内存，降低竞争、重复读取和生命周期错误。
- 每一帧都是完整绝对状态；新连接可立即显示，丢帧后无需补 delta，协议更容易验证。
- CivetWeb 与可执行文件同生命周期，部署只需要 EXE、SDL2 DLL 和静态网页目录。
- 浏览器进行地图投影和绘制，C++ 侧只负责可信的采样、规范化和传输。

## 数据模型与协议

协议版本为 v1。玩家 ID 以 JSON 字符串发送，避免 JavaScript 对 64 位整数丢失精度。帧包含：

- 序号、采集时间、地图 ID、当前玩家 ID；
- 玩家队伍、名称、竞技颜色、存活/休眠状态、世界坐标、yaw、生命、护甲、金钱、头盔、拆弹器、C4、当前武器和装备；
- C4 状态、位置或携带者、炸点、爆炸与拆除时序。

序列化器拒绝或归一化非有限浮点数，转义不安全字符，并且不发送进程地址。Steam ID 分享选项默认关闭，只有用户明确启用时才发送。

WebSocket 使用 `/api/v1/stream?token=...`。连接建立后会立即发送当前最新的完整快照（若已有），随后只向浏览器发送新快照；浏览器不能通过该连接控制游戏或写入内存。慢客户端只保留最新待发送帧，不创建无限队列。

## 固定地图坐标

地图清单位于 `web-radar/public/maps/manifest.json`，构建后位于 `web-radar/dist/maps/manifest.json`。投影遵循 Source overview 坐标：

```text
pixelX = (worldX - originX) / scale
pixelY = (originY - worldY) / scale
normalizedX = pixelX / imageWidth
normalizedY = pixelY / imageHeight
```

地图保持北向朝上，只有玩家方向图标根据 yaw 旋转。多层地图按玩家的 Z 坐标选择楼层图片；超出已知楼层高度时选择最近楼层，避免标记无故消失。

`scripts/sync_web_radar_maps.py` 下载固定版本且校验 SHA-256 的地图包，并生成 manifest、来源信息和 NOTICE。同步脚本本身与 Web Radar 代码是 clean-room 实现；雷达图片和 overview 数据属于 Valve，仍受 Valve 的版权与条款约束。发布时必须保留 `maps/NOTICE.txt` 和 `maps/SOURCE.json`。

## 服务与安全默认值

- 默认监听 `127.0.0.1:22006`，仅本机可访问。
- 局域网共享必须由用户主动将监听地址改为 `0.0.0.0` 或指定网卡地址。
- 每次进程启动都由 Windows 系统 CSPRNG 生成新的高熵 URL-safe token；只通过可信局域网传递完整 URL。
- token 是局域网访问门槛，不是 TLS：内嵌服务只提供 HTTP/WS，不应端口映射、公网暴露或穿透转发。
- 状态接口只公开服务健康信息，不返回 token、文件路径、游戏数据或内部错误细节。
- 服务启停幂等；退出、配置变更或游戏重连不能遗留监听线程。

建议在 Windows 防火墙中只允许“专用网络”。若确实需要跨不可信网络访问，应由用户在外部增加 TLS VPN，而不是直接开放端口。

## 生命周期与性能

建议的数据频率是：游戏快照可按现有高速缓存更新，而 WebSocket 对外发布限制在约 15–20 Hz。这样方向和移动足够平滑，同时限制 JSON 分配、锁竞争和网络广播成本。

服务采用“最新状态覆盖旧状态”的背压策略。每个观看者的延迟保持有界；浏览器短暂卡顿不会拖慢采样线程。前端基于时间戳插值炸弹计时，不需要为了倒计时提高推送频率。

默认随游戏失去前台焦点暂停采样。仅在离线共享展示确有需要时才启用后台采样；后台路径仍不得运行瞄准、扳机或任何写内存功能。

## 构建与发布

发布由三部分组成：

```text
external-cheat-base.exe
SDL2.dll
web-radar/
└── dist/
    ├── index.html
    ├── assets/
    └── maps/
```

前端使用锁文件执行 `npm ci`，然后运行 Vitest 和 Vite production build。MSBuild 的 post-build 步骤将已有的 `web-radar/dist` 复制到输出目录；CI 在编译 C++ 前生成该目录。Docker 构建用独立 Node 阶段生成相同静态文件，再进行 MinGW 交叉编译。

## 后续优化建议

优先级从高到低：

1. 增加无游戏进程的录制回放工具，把脱敏 `GameSnapshot` 写成测试夹具，做到地图 UI 的确定性回归测试。
2. 对 JSON 序列化和广播耗时增加轻量指标：帧大小、丢弃旧帧数、观看者数、最大发送延迟。
3. 增加地图包离线校验命令，在启动服务前检查 manifest、图片和 SOURCE 哈希，错误时在菜单中给出可操作提示。
4. 增加可选的队伍视角/隐私策略，例如隐藏姓名、只显示指定队伍；保持默认最小暴露。
5. 增加前端截图或 Playwright 视觉测试，覆盖 16:9、平板和手机尺寸以及多层地图切换。
6. 若未来数据规模明显增长，再评估预分配 JSON 缓冲或二进制协议；当前人数规模下，保持可审计的 JSON v1 更合适。
